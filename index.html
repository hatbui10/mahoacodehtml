🔐 Công cụ Mã hoá & Chống dịch ngược Code

Dán hoặc tải lên tối đa khoảng 5.000–10.000 dòng code (JS/HTML). Công cụ sẽ đóng gói toàn bộ code gốc vào trong nhiều lớp mã hoá, chia nhỏ, xáo trộn thứ tự, chèn code rác và kiểm tra chống sửa — khi người khác mở F12 họ chỉ thấy một đống dữ liệu vô nghĩa, không thấy code gốc của bạn.

⚠️ SỰ THẬT KỸ THUẬT BẠN PHẢI BIẾT: Không tồn tại cách mã hoá nào cho code chạy trên trình duyệt người xem mà “tuyệt đối không thể dịch ngược”. Lý do: trình duyệt của họ phải giải mã được thì mới chạy được — nên về nguyên tắc, người cực kỳ giỏi vẫn có thể chặn đúng khoảnh khắc code đã giải mã trong bộ nhớ. Công cụ này làm cho việc đó cực kỳ khó, cực kỳ tốn thời gian (đủ để chặn 99% người copy code, xem trộm F12, hoặc ném code vào AI nhờ viết lại). Muốn bảo vệ 100% phần logic quan trọng nhất (thuật toán, key, công thức tính tiền…), hãy đưa phần đó lên server/API của bạn — xem mục hướng dẫn ở cuối trang.

2) Tuỳ chọn mã hoá
Cắt càng nhiều mảnh + xáo trộn thứ tự → càng khó ghép lại bằng tay/AI.
Điền vào thì code chỉ chạy trên tên miền đó; bị copy sang web khác sẽ không chạy. Để trống = chạy mọi nơi. Thận trọng: điền sai là code không chạy ở đâu cả — hãy test kỹ.
Sau ngày này code tự ngừng chạy. Để trống = không hết hạn.
Sẵn sàng. Hãy dán code rồi bấm “MÃ HOÁ NGAY”.
3) Công cụ này đã làm gì với code của bạn?
Kỹ thuậtTác dụng chống dịch ngược
Mã hoá toàn bộ code gốc (XOR stream nhiều lớp + đảo khối + cộng/trừ byte ở mức cực hạn)Code gốc không còn xuất hiện dưới dạng chữ đọc được ở bất cứ đâu trong file kết quả. Mở F12 / View Source chỉ thấy dữ liệu Base64 vô nghĩa.
Cắt nhỏ + xáo trộn thứ tự mảnhFile bị cắt thành hàng chục mảnh và trộn thứ tự. Copy 1 đoạn ném cho AI cũng vô ích — AI không có đủ toàn bộ + không biết thứ tự + không có khoá.
Khoá mã hoá ngẫu nhiên mỗi lần bấmMỗi lần mã hoá ra 1 kết quả khác nhau hoàn toàn. Không có “công cụ giải mã chung” nào mở được.
Code rác & bộ giải mã giảChèn hàm rác, mảng chuỗi giả nhìn giống thật → người gỡ rối bị lạc hướng, tốn thời gian phân tích nhầm.
Kiểm tra chống sửa (checksum)Sửa/xoá dữ liệu đã mã hoá → code tự chết. Ngăn kiểu “xoá đoạn chống copy rồi dùng tiếp”.
Khoá tên miền / ngày hết hạn (tuỳ chọn)Code bị bê nguyên sang web khác hoặc dùng quá hạn sẽ không chạy.
4) Cách dùng kết quả & lưu ý quan trọng

• Chế độ JavaScript: tải file .js về, thay cho file JS gốc trên web của bạn (giữ nguyên cách nhúng <script src="..."> như cũ).
• Chế độ nguyên trang HTML: file .html tải về chính là trang hoàn chỉnh — mở lên là chạy, không cần file phụ.
• Code có import/export: hãy chọn chế độ ES Module. Code classic có import/export sẽ không chạy qua bộ giải mã thường.
• Luôn giữ lại file code GỐC ở nơi an toàn. File đã mã hoá dùng để chạy, không dùng để sửa tiếp — cần sửa thì sửa ở file gốc rồi mã hoá lại.
• Luôn test file đã mã hoá trên 1 trang thử trước khi đưa lên web thật, nhất là khi bật khoá tên miền / chống F12.
• Một số trường hợp đặc biệt có thể cần test kỹ: code phụ thuộc document.currentScript, code tự đọc nội dung của chính nó, hoặc web có CSP cấm eval. Nếu web bạn cấm eval theo CSP, cần cho phép hoặc chuyển logic lên server.

🛡️ Muốn chống ở mức “AI/máy tính cũng không viết lại được toàn bộ”? Cách duy nhất đúng về mặt kỹ thuật: đừng đưa toàn bộ logic xuống trình duyệt. Hãy giữ phần quý giá nhất (thuật toán lõi, bảng giá, key, kiểm tra bản quyền…) trên server của bạn và cho trình duyệt gọi qua API. Trình duyệt chỉ nhận kết quả, không nhận cách làm — khi đó không ai dịch ngược được thứ họ không hề có. Công cụ này + tách server là bộ đôi bảo vệ mạnh nhất cho web.

Công cụ chạy 100% offline trên trình duyệt của bạn — code của bạn không được gửi đi đâu cả.
